# 已有预言与免费刷新提示设计

## 背景

泽拉图在猜中一张预言牌后会获得下一张未知预言牌。后续让卡牌进场时，
每触发一张已经猜出的预言牌，就会获得一次免费刷新。相同预言牌可能重复
出现，且每一份都独立贡献一次免费刷新。

现有候选表已经提供“预言牌”按钮，但确认操作只会清空当前推理记录，没有
记录用户确认的是哪张牌。现有 `persist()` 和 `restoreState()` 也是空实现，
页面刷新后无法恢复整局状态。

## 目标

- 使用候选表已有的“预言牌”按钮记录已猜出的预言。
- 支持同一预言牌出现多次，并记录其重复次数。
- 在精准预测的推荐区显示每张推荐进场牌预计触发的免费刷新次数。
- 推荐仍以区分未知预言的信息增益为首要指标。
- 页面刷新后恢复当前正式服对局状态。
- 暂时隐藏时代服入口，但保留时代服代码和数据。

## 非目标

- 不在中间的进场卡牌选择按钮上显示免费刷新次数。
- 不增加独立的已有预言选择器。
- 不删除或重构时代服数据、模拟器及相关注册表。
- 不改变现有“接近”判定规则。
- 不增加框架、构建工具或后端服务。

## 交互设计

### 确认预言

候选表每行的“预言牌”按钮携带该核心牌的 ID。点击后，确认弹窗显示具体
牌名。用户确认后：

1. 对应预言牌的已有数量增加一。
2. 清空本轮进场推理记录。
3. 清空本轮手动排除记录。
4. 保留全部已有预言，开始推断下一张未知预言。

已经记录过的预言仍可再次确认，不禁用按钮，因为同一张预言牌允许重复出现。

### 已有预言列表

“精准预测”面板在推荐牌列表之前显示紧凑的已有预言区域。相同牌按
`牌名 x 数量` 聚合展示。

- 删除单张：对应数量减一，减至零时移除该牌。
- 清空全部：二次确认后清空所有已有预言。
- 空状态：显示简短的“尚未记录预言”，不占用大块空间。

普通的“清除全部进场记录”只清空当前推理，不删除已有预言。

### 推荐展示与排序

推荐卡继续显示现有信息增益，并新增“免费刷新 xN”。刷新数为零时也可以
显示，以保证指标含义明确；视觉权重应低于信息增益。

推荐使用字典序排序：

1. 信息增益降序。
2. 信息增益相同时，免费刷新次数降序。
3. 两者都相同时，保持原有稳定卡牌顺序。

信息增益始终优先，避免对局后期大量已有预言淹没未知预言的推理价值。

## 数据模型与计算

已有预言使用按核心牌 ID 计数的数据结构：

```js
knownProphecyCounts = {
  "黄金舰队": 2,
  "扎加拉": 1
};
```

免费刷新次数复用现有 `isClose(enteredCard, prophecyCard)` 判定：

```text
refreshCount(enteredCard)
  = sum(knownProphecyCounts[prophecyId])
    for each prophecyId where isClose(enteredCard, prophecyCard)
```

因此，同一张预言记录两次且能被某张进场牌触发时，会贡献两次免费刷新。

预言牌只能来自当前正式服核心包。恢复持久化状态时，不在核心包中的 ID、
非正整数计数和无法识别的数据都应被忽略。

## 状态持久化

使用一个带版本号的 `localStorage` 对象保存正式服当前对局：

- 已启用卡包。
- 本轮进场记录。
- 本轮手动排除项。
- 已有预言及重复次数。
- 推荐等级筛选。

写入应发生在所有相关状态变更之后。启动时恢复并校验数据；存储缺失、JSON
损坏、版本未知或部分字段无效时，应用应忽略无效部分并使用默认值启动。

切换任意扩展包意味着开始下一局，必须同时清空：

- 已有预言。
- 本轮进场记录。
- 本轮手动排除项。

随后保存新的空局状态并重新加载卡牌。

## 时代服处理

正式服/时代服切换控件在记牌器和模拟器界面中隐藏。时代服注册表、数据文件、
加载逻辑和模拟器支持均保留，不删除代码，以便未来需要时恢复。

应用默认进入正式服。本功能的持久化和已有预言逻辑只保证正式服行为。

## 实现边界

项目继续使用原生 HTML、CSS 和 JavaScript。计算与校验逻辑应优先写成小型纯
函数，再由现有 `App` 对象调用，避免把刷新计算直接散落在渲染代码中。

建议的逻辑边界：

- 已有预言状态校验与归一化。
- 单张进场牌的免费刷新次数计算。
- 推荐结果的稳定比较函数。
- 持久化状态的序列化与恢复。

## 测试与验收

至少覆盖以下行为：

1. 确认候选牌后记录牌名，并清空当前推理与排除。
2. 连续确认同一预言牌两次后显示数量二。
3. 可触发该重复预言的进场牌获得两次免费刷新。
4. 删除一次重复预言后数量和推荐刷新数都减少一。
5. 信息增益不同时始终优先按信息增益排序。
6. 信息增益相同时按免费刷新次数排序。
7. 两项都相同时保持稳定顺序。
8. 页面刷新后恢复整局状态。
9. 损坏或过期的持久化数据不会阻止页面启动。
10. 切换扩展包会清空已有预言、推理记录和排除项。
11. 普通清除进场记录不会删除已有预言。
12. 时代服入口不可见，但相关代码和数据仍存在。

完成后需要通过桌面与移动视口检查已有预言列表、推荐指标和确认弹窗，确保
文本不溢出、按钮不重叠，并验证页面在静态服务器下可正常运行。
